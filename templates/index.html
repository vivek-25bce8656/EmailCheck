Classification Framework (Assessment, Not Guaranteed Delivery)

Likely delivered

Address possesses valid RFC syntax and the domain resolves active mail-routing infrastructure (dedicated MX records or RFC 5321 A/AAAA host fallback). Delivery is plausible at the domain level; individual mailbox existence cannot be confirmed by DNS alone.

Likely to bounce

Definite failure condition detected: malformed email syntax, nonexistent domain (NXDOMAIN), RFC 7505 Null MX record (explicitly rejecting mail), or confirmed absence of both MX and host routing records.

Unknown

Conservative assessment: temporary DNS query timeouts, transient network disruptions, or resolver errors prevent establishing routing. A DNS timeout or lookup error is never assumed to be a bounce.

Methodology, Hosting Environment & Responsible Assessment

Why EmailCheck provides evidence-based assessments rather than absolute mailbox delivery claims:

  • Routing Evidence vs. Mailbox Existence: DNS MX records and host fallback records verify whether a domain has mail-routing infrastructure configured. They do not confirm whether an individual recipient inbox exists or is currently accepting messages. Truthful verification without sending an email or intrusive probing cannot guarantee mailbox deliverability.
  • Hosting Environment Constraints (Render Network Policy): Cloud hosting environments (including Render, AWS, and GCP) strictly block outbound connections on TCP port 25 to prevent spam relaying and abuse. Direct SMTP mailbox socket probes (e.g. HELO, MAIL FROM, RCPT TO) are blocked by cloud network security policies and cannot be performed in production. Furthermore, modern mail servers employ greylisting, anti-harvesting, and catch-all policies that make SMTP probing inaccurate and spam-like. EmailCheck uses standard UDP/TCP port 53 DNS queries to provide reliable, non-intrusive domain routing verification without port 25 dependencies.
  • RFC 5321 Fallback Mail Routing: When a domain lacks dedicated MX records, RFC 5321 Section 5.1 specifies inspecting the domain's IPv4 (A) and IPv6 (AAAA) addresses for implicit mail routing before concluding mail cannot be routed.
  • RFC 7505 Null MX Detection: If a domain publishes a Null MX record (target . with preference 0), it explicitly signals that the domain does not accept email. Under standards, implicit A/AAAA fallback routing does not apply and the address is classified as Likely to bounce.
  • Conservative Classification of Uncertain Cases: A temporary DNS timeout or lookup failure is never treated as proof that a domain cannot receive email. When network resolution is inconclusive, the address is classified as Unknown.
  • Spreadsheet Formula Injection Defense: When exporting assessment data to CSV, all fields are sanitized against formula execution (e.g., commands starting with =, +, -, @, \t, or \r), ensuring spreadsheet safety.
  • No Application-Level Address Storage: EmailCheck assesses email addresses purely in memory during request execution and does not persist, store, or sell submitted addresses in databases.
